## 零、先講最重要的一件事：這是健康資料

月經資料在 GDPR 屬於「特種個人資料」（health data），在美國屬於 HIPAA 之外但同樣高度敏感的
類別。2022 年之後歐美有大量報導提及經期 App 的資料被外洩、被用於廣告、甚至在司法程序中被
調取。**這件功能一旦做壞，傷害的性質和「日記存不了」完全不同。**

所以在寫第一行程式之前，先把界線釘死：

| 原則 | 具體做法 |
|---|---|
| 預設關閉 | 不主動出現在任何分頁。使用者要自己到設定裡打開，才會看到入口 |
| 只存本機 | 和夢境／日記同一套 `localStorage` + `IndexedDB` |
| 上雲一律加密 | 走既有的星塵帳號 E2E 加密同步（`account.js`，PBKDF2-SHA256 200k → AES-GCM），伺服器永遠只看得到密文 |
| 絕不進 API | 不送給 `api/ai-chat`，不進 Notion 同步，不進任何 webhook。夢汐不會知道你的週期 |
| 匯出時要再問一次 | 匯出 JSON／Markdown 時，週期資料預設**不含**，要另外勾選 |
| 隨時可整組刪除 | 設定裡一顆「刪除所有週期紀錄」，不需要連帶刪其他資料 |
| 不做醫療聲明 | 全程用「紀錄」「觀察」「對照」，不用「預測」「診斷」。免責聲明比水晶那套更明確 |

**這一段我建議不要為了做得快而妥協。** 使用者願意把這種資料放進來，靠的是這些界線。

## 一、這個功能到底在解決什麼

Stardust 已經有的東西：月相演算法（真實朔望時刻）、心情日曆（5 級心情 × 月相同格排版）、
夢境紀錄、CBT 思考紀錄。**這些資料本來就都帶日期。**

所以真正的價值不是「再做一個經期 App」——市面上已經很多，而且做得比我們好。
價值在於**把週期疊到既有的月相與情緒資料上**，回答一個別的 App 答不了的問題：

> 我的身體週期，和月亮的週期，和我的情緒，這三件事排在一起長什麼樣子？

這件事沒有醫學宣稱，是一種**自我觀察的視覺化**，而且完全符合 Stardust 現有的調性。

## 二、功能範圍（建議只做 v1，先不要貪）

### v1：紀錄 ＋ 對照（建議這次只做這些）

| 功能 | 說明 |
|---|---|
| 週期紀錄 | 標記經期開始／結束日；可選填流量（輕／中／重）與身體感受標籤（腹痛、腰痠、頭痛、脹、疲倦…） |
| 心情連動 | 直接沿用既有的 5 級心情與情緒標籤，不另做一套 |
| 週期日曆 | 在既有的月曆分頁**加一層**：格子底色標經期、上方仍是月相圖示，一眼看到兩個週期的相對位置 |
| 共時性視圖 | 一張圖：把最近 6 個週期的「經期起始日」標在月相環上，看看是否貼近某個月相 |
| 平均統計 | 平均週期長度、平均經期天數、最短／最長。**只呈現已發生的資料，不外推** |

### v1.5 以後（先不做，列在這裡備忘）

- 下次可能的起始日提示（要非常小心措辭：「依你過去 N 次的平均推算」，並且明確說不是預測）
- 週期階段 × 情緒的統計對照（例如「你在黃體期記錄到的『焦慮』比例較高」）——這是最有價值也最容易被誤讀的一塊，需要足夠樣本數才顯示
- 週期 × 夢境主題的對照（Stardust 有夢境符號標記，這個角度很少人做過）
- 週期 × 水晶推薦（要小心，別滑進療效宣稱）

### 明確不做

- 不做懷孕／避孕相關的任何推算。這是醫療器材等級的責任，不是我們的守備範圍。
- 不做「安全期」。同上，而且會害到人。

## 三、資料模型（草案）

```js
store.data.cycles = [
  {
    id: "…",
    start: "2026-07-12",        // 經期開始日
    end: "2026-07-17",          // 結束日；未結束時為 ""
    flow: { "2026-07-12": 2, "2026-07-13": 3, … },   // 1 輕 2 中 3 重，可不填
    symptoms: ["腹痛", "疲倦"],  // 自由標籤，沿用情緒標籤那套 UI
    note: "",
    createdAt: "…",
  },
];
store.data.settings.cycleEnabled = false;   // 預設關閉，使用者自己開
```

心情不另存：日曆對照時直接讀既有的 `store.data.moods`。

**月相不需要另存**：`moonInfo(date)` 與 `lunation()` 已經能算出任一天的真實月相與月齡，
共時性視圖直接用現成的函式。

## 四、介面放哪裡

延續上次的決定：**不加底部分頁按鈕**（那一列已經九顆）。

建議放在既有的「📅 月曆」分頁，用和宇宙分頁同一套子分頁樣式：

```
月相日曆 ｜ 心情日曆 ｜ 週期        ← 第三個只在 cycleEnabled 為 true 時出現
```

這樣既不新增按鈕，又剛好和「心情日曆」並列——因為它們本來就是同一件事的不同切面。
入口開關放在設定分頁，文案要寫清楚資料存在哪、誰看得到。

## 五、共時性視圖長什麼樣（這是這個功能的靈魂）

一個圓環，代表一個朔望月（29.53 天）：

- 環上以真實朔望時刻標出**朔（🌑）與望（🌕）**的位置
- 把最近 6 次的經期起始日，各畫一個點在環上對應的月相位置
- 點的顏色依時間由淺到深，越近的越深

如果那些點集中在環的某一段，使用者自己就會看見；如果散得很開，那也是一個答案。
**我們不下任何結論，只把圖畫好。** 圖下面一句話：

> 這是你的觀察紀錄，不是醫學結論。月相與生理週期長度接近是天文與生理的巧合，
> 目前沒有可靠證據顯示兩者有因果關係。

最後這句我建議一定要寫。它會讓這個功能顯得誠實，而誠實正是 Stardust 的調性。
